# V2 acceptance register

This register preserves the complete [product plan](product-plan.md), including all 92 numbered sections and the user's request to implement the complete product and setup. Section 92 is the minimum acceptance gate, not permission to discard the rest of the plan. The plan explicitly describes some items as examples, optional features, or future experimental directions; those distinctions are recorded rather than silently turning them into completed work.

- **Implemented**: the cited source implements the stated bounded behavior. Runtime verification may still be outstanding.
- **Partial**: meaningful implementation exists, but a listed behavior or its proof is missing.
- **Missing**: no V2 implementation was found for the requirement.
- **Direction**: the source explicitly makes the item optional, illustrative, or future. The contract/architecture requirement still applies, and the capability remains in the product roadmap; this label does not mean implemented.
- **Coverage present**: named tests exercise the bounded behavior in source. A fresh successful run against the final code is required before marking it verified.
- **Unverified**: source cannot establish the claim; collect runtime, browser, infrastructure, or device evidence.
